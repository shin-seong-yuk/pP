01 / MOTIVATION

단순한 수치 강화에서,
수식을 설계하는 전략으로.

학생들이 수학을 어렵게만 느끼지 않도록, 함수를 게임 속 선택과 결과로 경험하게 하고 싶었습니다. 일반적인 타워 디펜스의 단순한 수치 업그레이드에서 벗어나 수학 자체를 전략에 연결했고, 같은 포탑과 카드라도 수식 구성·배치·전력망에 따라 다른 전략을 만들도록 했습니다.

플레이어는 포탑마다 부여된 수학적 항과 연산 카드를 조합해 수식을 만들고, 시간에 따라 변화하는 포탑의 성능을 설계합니다. 직접 전투와 건설에도 참여하면서 자신의 전략을 실행합니다.

02 / SYSTEMS

선택이 서로 연결되는 전략 구조

무작위 항 · 연결해야 작동하는 규칙

설치한 포탑에는 무작위 항이 부여됩니다. 같은 종류의 포탑들의 항을 연산자로 연결해 식을 구성해야 해당 종류의 포탑들이 작동합니다. 불리해 보이는 분수 함수도 무조건 배제하기보다 주어진 항의 활용 방법을 고민하게 하려는 설계입니다.

건설 · 전력망

지형, 사거리, 전력 연결과 포탑 배치를 함께 고려하도록 구성했습니다. 수식뿐 아니라 어디에 설치하고 어떻게 연결하는지도 전략의 일부입니다.

직접 전투 · 성장의 출발점

포탑만으로 처치하면 플레이어 경험치는 오르지 않고, 플레이어가 직접 마무리한 적에게만 경험치를 줍니다. 레벨업으로 연산자와 포탑 카드를 얻어 방어를 강화하는 순환을 만들었습니다.

무작위 맵 · 판단의 여지

무작위 맵과 웨이브에서도 지형과 사거리, 배치에 대한 판단이 결과에 반영되도록 구성했습니다. 기획한 규칙은 직접 구현하고 실제 웹 배포 환경에서도 확인했습니다.

03 / DESIGN QUESTIONS

재미를 유지하기 위한 설계의 균형

접근성과 전략성
수학 시스템이 어렵게 느껴지지 않으면서도, 수식의 구성에 따라 전략적 차이가 생기도록 설계했습니다.
발견 · 초반 x³의 과도한 우위
초기에는 증가 함수만 있었고, 초반에 x³을 얻으면 포탑 하나로 40스테이지 이후까지 방어할 수 있었습니다. 강력한 함수 획득이 이후의 선택을 대체하는 문제로 보았습니다.
조정 · 함수와 등장 확률
분수 함수를 추가하고 x³·1/x³과 일부 연산자의 등장 확률을 낮췄습니다. 강력한 조합을 쉽게 얻는 상황을 줄이고, 다양한 함수를 접하게 한다는 기획 의도를 반영했습니다.
확인 · 정성 피드백
조정 후 직접 플레이에서 변화를 체감했습니다. 다른 사람에게 플레이를 부탁했을 때도 밸런스가 잡힌 느낌이라는 피드백을 받았습니다. 이는 플레이 체감에 대한 정성 평가입니다.
역할 분배 · 처치와 성장
직접 처치 → 경험치·레벨업 → 카드 획득 → 포탑 강화로 연결했습니다. 포탑을 설치한 뒤 관전하는 대신, 높은 점수를 위해 웨이브 중 직접 움직이며 전투에 참여하도록 설계했습니다.
무작위성과 플레이어의 실력
무작위 맵과 웨이브에서도 지형 판단, 배치와 전력망 설계가 의미 있는 선택이 되도록 구성했습니다.

04 / TROUBLESHOOTING

전략을 판단할 정보가
제대로 전달되는가?

Unity 에디터에서 정상적으로 동작하던 게임을 WebGL로 배포하자 한글과 일부 수학 기호가 사라지고, 발광 효과와 UI 아이콘이 의도와 다르게 표시됐습니다. 브라우저 콘솔과 Unity 로그를 분석해 현상별 원인을 분리했습니다.

폰트 누락

WebGL에서는 운영체제 폰트에 의존한 대체 글꼴을 안정적으로 사용할 수 없었습니다. 한글과 수학 기호를 포함한 폰트를 프로젝트 리소스로 추가하고, UI가 공통으로 사용하도록 적용 로직을 통합했습니다.

셰이더 제거

코드에서 런타임에 찾던 셰이더가 빌드 최적화 과정에서 제거되고 있었습니다. 사용하는 URP·UI·Sprite·Skybox 셰이더를 빌드에 명시적으로 포함했습니다.

아이콘 · 화면 비율

플랫폼마다 다르게 보이는 이모지를 AI로 제작한 텍스처 아이콘으로 교체했습니다. 실행 화면을 16:9로 고정하고 itch.io 임베드 영역을 조정해 UI가 잘리는 문제를 해결했습니다.

반복 검증 · 자동화

4일 동안 하루 6시간 이상 원인을 공부하고, 수정할 때마다 실제 웹에서 확인하며 10회 넘게 재배포했습니다. 반복되는 WebGL 설정은 전용 빌드 메뉴로 자동화했습니다.

그 결과 에디터와 itch.io 배포 환경에서 한글, 수학 기호, 아이콘, 발광 효과와 UI 배치가 일관되게 출력되도록 개선했습니다.

05 / REFLECTION

완성의 기준은 사용자의 경험.

이 프로젝트를 통해 제가 만족하는 상태보다, 실제 사용자가 의도한 경험을 할 수 있는 순간을 완성의 기준으로 삼게 되었습니다. 문제가 생기면 로그와 플랫폼 특성으로 원인을 분리하고, 일회성 수정에 그치지 않도록 반복 설정을 자동화하는 방식을 배웠습니다.
